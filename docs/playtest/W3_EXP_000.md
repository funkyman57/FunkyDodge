# W3-EXP-000 — Minimal Binary World-State Proof

Isolated World-State diagnostic. **Not** Human Validation. **Not** W3 room production. **Not** Door / Switch implementation.

**Classification:** **PASS**

This proves the **physical** W3-K01 relation exists. It does **not** prove a player can perceive, trigger, or plan around it.

---

W3 POSSIBILITY needs a persistent binary World State that changes a **real action possibility** without a new movement technique.

## Source inspection

Solidity today is two layers:

1. Phaser Arcade **static collider** (`physics.add.existing(rect, true)` + `physics.add.collider(player, platforms)`).
2. A copied AABB list on `PlayerController` for geometric wall contact and distance-to-ground.

There is no existing World State / trigger abstraction.

Collision can be disabled with `StaticBody.enable = false` without recreating the body. If only Arcade collision is disabled, the AABB list would still treat the object as a wall. PASSABLE therefore removes the probe from **both** layers.

Re-solidifying while the player overlaps a static body is unsafe in Arcade (undefined / explosive separation). EXP-000 does **not** invent a production solution. Diagnostic constraint: refuse SOLID while overlapping.

---

## State model

Diagnostic object: `WorldStateProbe` (not a Gimmick ID).

| State | Collision | Controller solids | Visual |
| --- | --- | --- | --- |
| SOLID | Arcade body enabled | AABB included | Filled slab + thick outline + `PROBE SOLID` |
| PASSABLE | Arcade body disabled | AABB excluded | Hollow / low-fill + thinner outline + `PROBE PASSABLE` |

Persistent. Deterministic. No timer, cycle, force, special bounce, or hidden third state.

Known rule only: ordinary solidity vs ordinary pass-through when collision is off.

## Scenarios

Same start, same motion, same geometry. Only World State changes.

**Condition A — SOLID** and **Condition B — PASSABLE**

Traversal pose: x=260, y=450, vx=280, vy=0, 36 frames @ 60 Hz, radius 16.

Probe AABB: left 320, right 348, top 400, bottom 516.

Support pose (same binary state, second measurement): x=334, y=360, vx=0, vy=240.

No LOW / BOOST / Wall Jump / AR / Charge in the measurement.

## Overlap / re-solidification

Observed need: if PASSABLE → SOLID while the player AABB overlaps the probe, Arcade static separation is unsafe.

**Diagnostic constraint (not a gameplay rule):** `setWorldState(SOLID)` is refused while overlapping. HUD: `W3 toggle refused (overlap)`. Toggle is allowed when the player is clear.

This constraint is tested. It is not hidden as future Door behavior.

---

## Classification

**PASS**

A persistent binary World State, using the existing collision relation, creates a clean deterministic action-possibility difference under comparable Player State.

The overlap refuse is a diagnostic safety constraint, not a confound of the A/B comparison (those launches never re-solidify on top of the player).

PASS does **not** validate human understanding of W3-K01.

---

## Door / Switch

Door is **not** required to expose this K01 relation. SOLID/PASSABLE is the same core physical contrast a Door would use (blocked vs passable space). Door would add object-role language and a production visual, not a new physical law.

A dedicated player-facing Switch is **not** required to prove K01. Diagnostic control is enough. This does **not** answer W3-K02.
