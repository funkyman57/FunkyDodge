## Temporal scheduler model

Diagnostic phases — **not** World State values:

| Phase | Meaning |
| --- | --- |
| IDLE | no scheduled transition |
| PENDING | future PASSABLE is scheduled |
| SETTLED | PASSABLE write completed |

Ontology while PENDING:

- World State: **SOLID**
- Temporal relation: **PASSABLE scheduled**
- Future World State: **PASSABLE**

Pending is not semi-solid, reduced collision, a special bounce, or a third Gimmick state. `probeCollides` still equals `state === "SOLID"`.

Implementation: `src/game/debug/WorldStateDelay.ts` (`stepDelay`).

Safest insert: PlaygroundScene calls `stepDelay` instead of `stepAgency` when DELAY is on. Tests for W3 still call `stepAgency` and stay valid.

## Cause acknowledgement

Fresh activator contact while IDLE:

- `causeAcknowledged = true` on that same step
- phase becomes PENDING
- probe stays SOLID
- progress begins (`elapsedMs = dt`, first frame ≈ 0.023)

The player can distinguish "activation succeeded" from "nothing happened":

- activator label: **CAUSE ACK**
- probe label: **PENDING EARLY** plus meter growth
- HUD: `CAUSE ACK` / `W4 PHASE PENDING` / `FUTURE PASSABLE`

## Progress representation

Continuous progress `elapsedMs / 720`, clamped to `[0, 1]`, plus truthful bands:

| Band | Progress |
| --- | --- |
| NONE | 0 |
| EARLY | (0, 1/3) |
| MID | [1/3, 2/3) |
| LATE | [2/3, 1) |
| COMPLETE | 1 |

Visible on the probe, not color-only:

- vertical meter height = actual progress
- tick marks at 1/3 and 2/3
- chevron count `>` / `>>` / `>>>` / `>>>>` matches the band
- phase label includes band + percent

The meter is tied to `session.progress`. Completion of the meter is the same step that writes PASSABLE.

HUD text is extra. It is not the only evidence.

## Delay value

**720ms** diagnostic only. Not a production Timed Gate band.

Why this band for EXP-000 (relation proof, not optimization):

- long enough to read PENDING (tens of frames)
- long enough for one known W3 action (support / traversal pose = 36 frames / 600ms)
- short enough that cause and completion stay connected (< 1s)
- not a reaction window
- not an idle-wait (not 2–3s)

At `dt = 1/60`:

- pending frame 1 (ACK): 16.67ms, progress 0.023
- pending frame 22 (mid): 366.7ms, progress 0.509
- pending frame 43 (late): 716.7ms, progress 0.995 — still SOLID
- pending frame 44: elapsed ≥ 720ms → SETTLED PASSABLE

## Reactivation contract (experiment only)

WHILE PENDING: fresh activator contacts are **IGNORED**.

- no restart
- no cancel
- no reverse
- no queue (`queuedEvents` is always 0)
- no extra pending event
- no hidden cooldown

Ignored contacts increment `ignoredReactivations` and set HUD `IGNORED REACTIVATION`.

Auto Bounce repeated contact on the solid activator post stays a held overlap (no extra rising edge), same as W3 Model B.

This is **not** a production rule.

## Completion

When `elapsedMs >= 720`:

- `setWorldState(probe, "PASSABLE")`
- phase SETTLED
- progress 1
- pending cleared (`futureState = null`)
- PASSABLE persists

No auto-revert. No expiry. No cycle.

SOLID → PASSABLE overlap at completion is safe in the existing W3 model. Inspected: completion uses the same `setWorldState` write; collision drops both Arcade static body and controller AABB via the existing probe view.

## Restore / reset

After SETTLED:

- **RESTORE NOW** / activator contact / `restoreDelayImmediately` writes SOLID immediately and returns IDLE
- **R / RESET** uses `resetDelaySession` → IDLE, SOLID when the occupant is clear

Immediate restore is **diagnostic recovery**, not a production temporal contract. EXP-000 isolates delayed **onset** only. Restore does not use the 720ms delay. That avoids a second temporal rule.

PASSABLE → SOLID overlap refuse remains the existing W3 constraint. It is not part of temporal knowledge.

## Scenarios

**A — CAUSE ACK.** SOLID / IDLE → fresh contact → ACK, SOLID, PENDING, progress 0.023.

**B — MID-PENDING.** 366.7ms / 0.509 MID → SOLID, SUPPORT yes (y=384), TRAVERSAL blocked (x=304).

**C — COMPLETION.** Frame 44 of pending → PASSABLE / SETTLED. SUPPORT gone, TRAVERSAL x=428. Holds after +120 frames.

**D — REACTIVATION.** Mid-pending recontact: `ignoredReactivations=1`, `queuedEvents=0`, progress 0.301 → 0.347 (continues, does not restart).

**E — RESTORE.** After SETTLED, immediate SOLID / IDLE. X support returns, Y traversal closes. Original W3 physical relation.
