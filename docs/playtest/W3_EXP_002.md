## X / Y definitions

**X — SUPPORT (SOLID only)**

Be supported by the probe top and hold that height. Measured: start 334,360, vy=240 → final y=384, `supported=true`.

This is not "waiting." It is a real W1 collision use: stand on the object.

**Y — TRAVERSAL (PASSABLE only)**

Pass through the occupied space to the far side. Measured: start 260,450, vx=280 → final x=428, `traversed=true`.

Ordinary pass-through. No extra behavior.

Both are useful. SOLID is not merely the inconvenient state before PASSABLE. PASSABLE is not merely progress.

## Scenarios

### CORRECT — X while SOLID → change → Y

```
State SOLID. Action: use X (support). Result: y=384.0 supported=true
Cause: Model B activator contact. State SOLID → PASSABLE. refused=0
State PASSABLE. Action: use Y (traverse). Result: x=428.0 traversed=true
```

Combined goal (visit X and Y): **valid**. Overlap refuse not used.

### EARLY — change first → attempt X

```
Cause first: activator contact. State SOLID → PASSABLE. refused=0
Attempt X (support) while PASSABLE. Result: y=504.0 supported=false
Y remains available: x=428.0 traversed=true
```

X is physically unavailable. Combined goal fails unless the player restores.

### RESTORE

```
PASSABLE. Attempt X. Result: y=504.0 supported=false
Restore: activator contact. State PASSABLE → SOLID. refused=0
SOLID. Use X again. Result: y=384.0 supported=true
```

Restoration makes mistakes cheap. It does **not** make order meaningless: while PASSABLE, X is still gone. The player can still observe "I needed X before switching to B."

W3 does not require irreversible commitment.

### DIRECT Y — PASSABLE is correct for a Y-only plan

```
State PASSABLE from the start. Action: use Y only. Result: x=428.0 traversed=true
```

PASSABLE is not globally wrong. State value depends on the intended action.

## Player-State carryover

Route progress: X visited while SOLID. After X the player is at the supported height (y=384), then leaves the probe **before** changing so overlap-refuse is not part of the sequence.

Not carried momentum. Not W2.

The retained consequence that enables the combined goal is: X has already been used while it existed. After the change, only Y remains.

---

## Logical-order proof

For the combined goal (X and Y):

1. Y requires PASSABLE.
2. X requires SOLID.
3. One binary state cannot be both at once.
4. Changing first removes X.
5. Therefore X must be used before the change if the player wants both.

No timer. Waiting in either state does not alter the table.
