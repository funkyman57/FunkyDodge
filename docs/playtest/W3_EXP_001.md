# W3-EXP-001 — Intentional State Change & Recovery

Isolated World-State agency diagnostic. **Not** Human Validation. **Not** Door / Switch production. **Not** K03 / K04.

**Classification:** **PASS**

**Model verdict:** **SEPARATE ACTIVATOR PREFERRED**

This is **not** Switch approval. It means separating STATE USE from STATE CHANGE is currently the cleaner interaction model.

---

## Purpose

EXP-000 proved a persistent SOLID / PASSABLE World State can change a real action possibility under the same Player State.

This experiment asks whether the **player** can intentionally:

- cause the state change
- avoid the state change
- restore the previous state

without ambiguous contact semantics.

Target: **W3-K02** — my action changes World State, and that changes what I can do next.

Not tested: K03 trade-off, K04 ordering, mastery, human readability.

## Grammar

Implemented grammar: **TOGGLE** on a **fresh-contact rising edge**.

One intentional contact → one state-change event. Multi-frame overlap does not multiply transitions. No time cooldown.

**TOGGLE vs explicit SET (audit, not a library rule):**

| | TOGGLE | Explicit SET |
| --- | --- | --- |
| Object count | One cause can both change and restore | Needs at least two causes, or a second recovery path |
| Auto Bounce | A second landing / re-contact reverses intention | Repeating the same cause does not undo |
| Tracking | Player must remember current state | Cause names the destination |
| Burden | Extra contact is dangerous | Extra object count |

TOGGLE is the smallest implementation that supports recovery with one cause. It is **not** generalized into the final rule library. A floor-pad + TOGGLE would retrigger on Auto Bounce. Model B therefore uses a **side post**, not a bounce pad.

## Model A — self-activating object

The WorldStateProbe owns SOLID / PASSABLE **and** receives the change.

Cause: overlap-only left-face strip (x 308–320, y 416–516). Not a new collider. Top support stays ordinary use.

- Fresh touch of the left-face strip **toggles** the probe.
- Standing on top does **not** toggle.
- Using the left face as a wall **does** toggle — USE and CHANGE share that face.
- After PASSABLE, the strip remains a ghost overlap region because ordinary collision is gone.
- Restore from the left works if the player is not overlapping the probe.
- Restore while overlapping the probe is **refused**.

Avoidability: **CONDITIONALLY OPTIONAL**. A mid-height approach from the left is the natural contact and will change state. Going over the top, or using the top as a platform, avoids the cause.

---

## Model B — separate activator

`WorldStateActivator` (neutral diagnostic name, not a Gimmick ID).

A thin always-solid post at x 80–92, y 400–516. Gap to the probe is larger than the player. The post only changes WorldStateProbe state.

- Fresh side contact **toggles** the probe.
- The activator stays solid after the probe becomes PASSABLE, so recovery remains reachable.
- Using the probe (block / support / later traversal) does not touch the activator.
- Player AABB cannot overlap activator and probe at once.

Avoidability: **CLEARLY OPTIONAL**. The same start can go right (use the probe, no change) or left (cause).

## Auto Bounce / multi-frame contact

Fresh-contact rising edge, not a timer.

| | Held overlap frames | Transitions |
| --- | --- | --- |
| Model A HOLD | 10 | 1 |
| Model B HOLD | 42 | 1 |
| Model A RECONTACT (leave + return) | 10 max | 1 transition + 1 refuse |
| Model B RECONTACT (leave + return) | 14 max | 2 (second contact is a new intention) |

One approach that stays in contact = one event.

A **new** contact after departure is a second event. That is correct for rising-edge, and it is why a floor Auto Bounce pad + TOGGLE would flip twice. Model B avoids that by using a wall post. No cooldown was added.

Model A recontact from the opposite side often overlaps the probe while PASSABLE, so the second edge is **refused**. Recovery is direction-dependent.

## Overlap safety

Policy compared:

| Policy | Used? | Safety | Semantic cost |
| --- | --- | --- | --- |
| A. Refuse while overlapping | **Yes** | Safe | Restore can fail; HUD shows refuse. Honest, but a hidden-feeling exception if treated as a game rule. |
| B. Restoration cause cannot be reached while overlapping | Model B **geometry** | Safe | Player-facing: go to the other object. |
| C. Queue until clear | **No** | Safe later | State changes after the action. Conceptually dishonest. |
| D. Teleport / extra exception | **No** | — | Hidden rule. |

Model A overlap-refuse case: start inside/through PASSABLE space, rising edge while overlapping → state stays PASSABLE, `refused 1`.

Model B: activator and probe are separated by more than a player diameter. Restore while standing on the activator does not occupy the probe.

EXP-001 does **not** promote refuse into a production Door/Switch rule.

## Classification

**PASS**

Model B supports intentional cause, meaningful avoidance, clear restoration, one-action / one-transition semantics, and safe physical changes, without new player input, timing pressure, or a hidden cooldown.

Model A also has agency, but it keeps **SELF-CONTACT AMBIGUITY**, **RECOVERY** direction dependence, and **OVERLAP SAFETY** refuse burden. That is not enough to fail the experiment, because at least one model is clean.

---

## W3-K02

The physical agency relation exists: a player-initiated contact can change World State, and that change alters what the same movement can do next (block vs traverse / support vs fall-through).

This does **not** validate that a human reads, plans, or prefers that relation.

---

## K03 / K04 future seam

Do not implement those puzzles here.

**K03** (gain one possibility, lose another): Model B leaves a cleaner seam. The player can still use the probe as SOLID, then change it, then use PASSABLE, without the change being the same contact as the use. Model A spends the left-face use in order to change.

**K04** (use X first → change → use Y): Model B does not force a specific order by activation itself, and does not destroy access to the activator when the probe becomes PASSABLE. Model A can destroy ordinary contact with the cause when it becomes PASSABLE, and restore can be blocked by overlap refuse.

---

## Door / Switch

Door is still **not** required. SOLID / PASSABLE remains the physical relation.

A dedicated production Switch is **not** approved. EXP-001 only finds that **separating the cause object from the stateful object** is currently cleaner than self-activation. That is an interaction-model result, not a Gimmick lifecycle promotion.
